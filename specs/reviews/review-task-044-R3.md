# Review: Task 044 - Round 3

## Findings

- [-] **F1: Gen guard prevents cross-type animator cancellation, leaving stale `isAnimating` state** [process-revision-complete] -- The generation guard (`view.#zoomRegistrationGen !== gen`) in cancel handlers correctly prevents the R2 double-cancel on same-instance reuse (e.g., two consecutive `ZoomAnimator` uses on `'zoom'`). But when *different* animation types compete for the `'zoom'` property (e.g., `ZoomAnimator` replaced by a pan animation, or `ZoomOutAndBackAnimator` replaced by a `ZoomAnimator`), the gen counter has already been incremented by the new registration method, so the old cancel handler no-ops and the old animator is never cancelled. Pre-task-044, `#startAnimation` explicitly called `this.#zoomAnimator?.cancel()` and `playZoomOutAndBack` explicitly called `this.#zoomAnimator?.cancel()`. Task-044 removed these explicit cancellations, relying on the coordinator's cancel handler. But the gen guard defeats this for cross-type transitions, leaving the old animator in `isAnimating === true`. In degraded mode (lines 704-725), the skip-to-end code checks `zoomAnimator.isAnimating` and `zoomOutAndBackAnimator.isAnimating` independently of which animation is actually registered with the coordinator. A stale animator causes skip-to-end to apply its final state (zoom level + focus point), corrupting the active animation's viewport state. Concrete trace: (1) `animateToNode` starts ZoomAnimator targeting level 1.0; (2) after 3 frames, `centerOnNode` starts pan animation via `#registerPanAnimation` (gen increments); (3) coordinator fires old zoom cancel handler -- gen mismatch -- no-op; (4) ZoomAnimator remains `isAnimating === true`; (5) degraded frame fires: `zoomAnimator.skipToEnd()` sets zoom level to 1.0, then `this.#animation` sets focus to pan target -- zoom level is now permanently wrong. The fix is to explicitly cancel sibling animators in each `#register*` method (e.g., `#registerPanAnimation` should call `this.#zoomAnimator?.cancel()` and `this.#zoomOutAndBackAnimator?.cancel()`). Additionally, `#zoomAnimFrames` (line 686) is incremented continuously as long as `coordinator.isActive('zoom')` regardless of animation type change. When a zoom animation (3+ frames) transitions to a pan, the counter carries over and immediately triggers skip-to-end on the first pan frame in degraded mode. The counter should reset when the animation type changes. File: `src/limb/tree/LimbTreeView.mjs:561`. Spec ref: `interaction-feel.md S7.4`.

## Verdict
